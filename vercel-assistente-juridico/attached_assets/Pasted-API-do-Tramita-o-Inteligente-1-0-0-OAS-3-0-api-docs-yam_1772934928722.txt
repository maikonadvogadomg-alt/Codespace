🚀 Documentação da API da plataforma Tramitação Inteligente, permitindo a integração com sistemas externos.

👥 Público alvo
Como toda API, é destinada a desenvolvedores. Se você não é desenvolvedor (ou não tem um desenvolvedor), e deseja integrar o Tramitação Inteligente com algum outro sistema, preencha o formulário nesta página solicitando que nosso time desenvolva a integração.

📖 Documentação
A documentação da API pode ser consultada nesta página (que inclusive é interativa e permite testar as requisições usando seu token diretamente) ou, se preferir, baixando a especificação OpenAPI em YAML para utilizá-lo com sua ferramenta de IA preferida.

💰 Custo
A API é oferecida sem custo adicional para os assinantes do Tramitação.

📞 Suporte
Para solicitar acesso ou reportar problemas, utilize o formulário de suporte.

🔐 Autenticação
Esta API utiliza autenticação por token.

🔑 Como obter um token de API:
Tokens de API são gerados e gerenciados através do painel de controle. Clique aqui para gerenciar suas chaves de API.

📝 Usando o token
O token deve ser fornecido no header Authorization, com o valor Bearer SEU_TOKEN_DE_API_AQUI. Por exemplo:

Authorization: Bearer 7a7cafca351f47a7e...
Ou seja, o nome do header é Authorization; já o valor é Bearer SEU_TOKEN_DE_API_AQUI (não se esqueça de incluir a string 'Bearer ' antes do token).

🎮 Autenticação na documentação interativa
A presente documentação utiliza SwaggerUI e, portanto, é interativa, sendo possível fazer requests diretamente a partir dela.

Para tanto, é necessário se autenticar, clicando no botão 'Authorize' abaixo e informando seu token de API.

🔔 Webhooks
A API suporta webhooks para notificar aplicações externas sobre eventos importantes.

Os webhooks podem ser configurados através do painel de configuração. Cada evento enviará um payload JSON com os dados do recurso afetado.

Os seguintes eventos estão disponíveis:

Eventos de Cliente:
customer.created - Cliente foi criado
customer.updated - Cliente foi atualizado
customer.destroyed - Cliente foi removido (payload contém apenas o ID)
Eventos de Usuário:
user.created - Usuário foi criado
user.updated - Usuário foi atualizado
user.destroyed - Usuário foi removido (payload contém apenas o ID)
Eventos de Publicação:
publications.created - Novas publicações judiciais foram importadas. É necessário configurar previamente as OABs monitoradas em painel de configuração.
O payload contém um array de publicações e é enviado diariamente após o término da importação das publicações do dia.

Eventos de E-mail do Cliente:
customer_inbound_email.created - E-mail recebido no endereço exclusivo do cliente
Quando é disparado:

Quando um e-mail é recebido no endereço exclusivo do cliente (ex: abc123@email.tramitacaointeligente.com.br ou similar)
NÃO dispara para e-mails bloqueados (spam, vírus, etc.)
Importante:

URLs dos anexos apontam para o endpoint GET /uploads/{iid} da API, que requer autenticação e retorna um redirect para URL temporária de download
Requer plano ativo (trial, básico, ouro ou cortesia) para receber conteúdo completo
Sem assinatura ativa, o payload contém apenas ID, customer_id, created_at e uma mensagem
Veja o exemplo de payload na seção Schemas, em CustomerInboundEmailCreatedPayload, ou, se preferir, veja o exemplo abaixo:

🔄 Idempotência
Para garantir o processamento seguro dos webhooks, cada entrega inclui uma chave de idempotência:

Header: X-Webhook-Idempotency-Key contém o ID único do evento
Payload: Campo idempotency_key no JSON também contém o mesmo ID
A chave de idempotência representa o evento de negócio único que ocorreu. Use esta chave para:

Detectar e evitar processamento duplicado do mesmo evento
Identificar tentativas de reenvio (retry) do mesmo evento
Garantir que o mesmo evento recebido em múltiplos endpoints seja tratado como único
Importante: A mesma chave será usada em todas as tentativas de entrega (incluindo retries) e em todos os endpoints que recebem o mesmo evento.
