O `git rebase` é uma ferramenta poderosa que permite reescrever o histórico de commits de um branch. Ele é frequentemente usado para manter um histórico de commits limpo e linear, especialmente em projetos onde a integração contínua é importante.

Neste artigo, vamos explorar o que é o `git rebase`, por que e quando usá-lo, como funciona e como resolver conflitos que possam surgir.

## O que é Git Rebase?

Em termos simples, o `git rebase` é um comando Git que integra as alterações de um branch em outro, movendo ou combinando uma sequência de commits para um novo commit base. Ao invés de criar um novo commit de merge, o `rebase` reescreve o histórico, fazendo parecer que o trabalho foi desenvolvido diretamente a partir do branch base mais recente.

A imagem abaixo ilustra a diferença fundamental entre `git merge` e `git rebase`:

![Git Merge vs Git Rebase](https://i.imgur.com/2s3Kz2X.png)

*   **`git merge`**: Cria um novo commit de merge que une os históricos de dois branches, mantendo o histórico original de ambos. O resultado é um histórico de commits não linear, mas que preserva o contexto exato de quando as alterações foram mescladas.
*
